# Admin Pro 后台管理系统 - 使用与学习说明书

欢迎使用本 React 快速入门教学项目！本项目是为您量身打造的**简洁、可直接运行且极具设计感**的后台管理系统前端模板，主要用于快速掌握 React 18 及其相关生态的核心特性。

---

## 🚀 1. 快速启动

本项目完全不需要配置真实的后端服务器即可运行，所有的接口请求均通过本地拦截器（Axios Interceptor）和浏览器缓存（LocalStorage）实现。

**运行步骤：**
1. 确保您的电脑已安装 Node.js (推荐 v18+)。
2. 在项目根目录（即 `d:\dev\react-demo`）打开终端。
3. 运行项目启动命令：
   ```bash
   npm run dev
   ```
4. 在浏览器中打开终端中显示的本地地址（通常是 `http://localhost:5173`）。

**测试账号：**
- **用户名：** `admin`
- **密码：** `123456`

## 🛠️ 2. 技术栈解析

本项目严格遵守了需求文档中的技术选型，非常适合学习最新的前端标准：
- **核心框架：** React 18 (全部使用函数式组件 + Hooks)
- **构建工具：** Vite + TypeScript
- **路由管理：** React Router v6.4+ (使用嵌套路由与路由守卫)
- **状态管理：** Context API (轻量级全局状态管理，未使用 Redux)
- **网络请求：** Axios (配合自定义 Mock 适配器)
- **UI 组件库：** Ant Design 5.x (使用高定制化的主题配置)

## 🎨 3. 系统功能导览

登录系统后，您将看到采用了 **毛玻璃特效 (Glassmorphism)** 和 **现代渐变色** 设计的极简后台。

- **登录页 (`/login`)**
  - 功能：支持受控组件的表单校验，登录成功后将 Token 存入 localStorage。
  - 学习点：`antd` Form 组件校验、动态 CSS 动画。
  
- **仪表盘 (`/dashboard`)**
  - 功能：使用动态的卡片和纯 CSS 实现的动态统计图表，展示系统的核心指标（用户总数、角色数等数据会根据真实数据变化）。
  - 学习点：`Promise.all` 并发请求数据，并绑定至 UI 展示。

- **用户管理 (`/users`)**
  - 功能：实现了完整的增、删、改、查 (CRUD)。支持新建用户、弹出模态框编辑用户资料、通过气泡确认框删除用户。
  - 学习点：`antd` Table 的列定义及数据绑定，弹出层 Modal 的状态控制，Form 的数据回显 (`form.setFieldsValue`)。

- **角色管理 (`/roles`)**
  - 功能：使用卡片列表（Card List）展示不同的角色及其权限，并支持动态编辑。
  - 学习点：多选框 (Checkbox Group) 数据流，网格列表布局。

- **个人中心 (`/profile`)**
  - 功能：通过 Tabs 切换“基本信息”和“安全设置”表单。
  - 学习点：利用全局 `UserContext` 回显当前登录用户的信息。

## 📚 4. 重点学习指南（源码在哪看？）

作为学习项目，建议您按照以下顺序阅读源码：

### 第一步：理解路由与权限拦截
- **文件：** `src/router/index.tsx` 和 `src/components/AuthRoute.tsx`
- **知识点：** 查看 React Router v6 是如何通过 `createBrowserRouter` 定义嵌套子路由的；查看 `AuthRoute` 是如何判断本地是否存在 token 来决定放行还是跳转至 `/login` 的。

### 第二步：理解全局状态管理 (Context)
- **文件：** `src/store/UserContext.tsx`
- **知识点：** 这里定义了全局共享的 `User` 对象。通过 `createContext` 和 `useContext`，在组件中可以随时调用 `user` 信息或执行 `logout()` 退出登录，而无需复杂配置 Redux。

### 第三步：理解请求与 Mock 原理（核心）
- **文件：** `src/utils/request.ts` 和 `src/mocks/adapter.ts`
- **知识点：** 
  1. 在 `request.ts` 中，我们为 Axios 配置了请求拦截器（自动带上 Token 头）和响应拦截器（统一处理 401 报错）。
  2. 在 `adapter.ts` 中，我们写了一个自定义适配器。它会拦截所有发送到 `/api` 的请求，延迟 500 毫秒（模拟网络），然后**直接对浏览器的 `localStorage` 进行真实的增删改查**。这也就是为什么您在这个系统里添加用户，刷新页面数据依然存在的原因！

### 第四步：理解组件如何调用接口并刷新视图
- **文件：** `src/pages/User/UserList.tsx`
- **知识点：** 观察 `useEffect` 是如何做初始化数据请求的，以及 `fetchUsers()` 函数在用户删除或编辑成功后是如何被再次调用以**刷新表格**的。
